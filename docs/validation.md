# 검증 범위와 현재 남은 연결

기준일: **2026-10-24**. 코드·도구 검사와 과거 팀 환경의 실행 기록을 분리한다. 과거 성공 기록이 오늘의 서버 가동이나 전체 앱의 완성을 의미하지 않는다.

## 2026-10-24 로컬 연동 코드 검증

격리된 새 MySQL 8.4 환경에서 Java 21의 `check bootJar --rerun-tasks`를 실행했다. **JUnit 192개 전부 통과, 실패·오류·skip 0**, MySQL 이행 7개를 포함한다. Python 실행 도구 **120개**, 배포 설정 **71개**, [브라우저 V2 클라이언트](../integration/tests/estate-client.test.mjs) **15개**도 통과해 총 **398개**다. 기존 시연 DB는 사용하지 않았다.

이번 변경은 빈 AI 결과의 준비 상태 진입·기존 데이터 덮어쓰기 차단, 검증 로컬 가구 6종·단일 range·조건부 읽기, 사진 4장과 명시 modelId를 유지하는 인증 업로드 클라이언트다. 가구 가져오기 도구는 기존 파일을 네트워크 없이 검증하고 별도 런타임에 복사한다. 실제 가구 파일·사진·DB·키는 공개 커밋에 포함하지 않는다. 실제 Kakao·GPU 추론을 이 검사 수로 대신하지 않는다.

별도 임시 H2 서버와 모의 AI HTTP 서버에서 V2 클라이언트의 사진 4장 업로드, Outbox 명령·사진 읽기·단계별 callback, 보정·재구성, 기존 가구 포함 GLB의 실제 검증 저장, 공개 매물·지도·파일 재조회를 81개 조건으로 확인했다. 사진은 로컬에 보존한 팀 원본이며 외부 서버로 전송하지 않았다. 실제 GPU 계산과 새 가구 편집 UI를 실행한 증거는 아니다.

## 2026-10-21 공개 사본 로컬 재검증

Java 21에서 `check bootJar --rerun-tasks` 성공. 최초 실행에서 Docker 부재로 건너뛴 MySQL 검사는 별도의 새 임시 MySQL 8.4 환경에서 전체 재실행했다. **JUnit 170개 전부 통과·실패 0·skip 0**이며 MySQL migration 7개도 포함한다. Python `scripts/tests` 112개와 `deploy/tests` 71개도 모두 통과해 로컬 총 통과 수는 **353개**다. 임시 DB만 사용·종료했고 기존 시연 DB는 사용하지 않았다. CI는 Docker와 MySQL 7개 skip=0, Compose 및 컨테이너 빌드를 별도로 확인한다. 로컬 Docker 이미지 빌드는 미실행이며 원격 결과는 Actions에서 확인한다. 과거 10/16 준비 도구 135개와는 다른 실행이다.

## 공개 코드에서 재현할 검사

최신 공개 사본 검사는 저장소의 **GitHub Actions 실행 결과**와 아래 테스트 소스를 참조한다. 검사 수·실행 환경은 해당 실행 결과를 기준으로 읽는다.

| 검사 | 확인하는 범위 | 확인하지 않는 범위 |
|---|---|---|
| Kotlin/JUnit | 도메인·권한·상태·미디어·Outbox의 정상/거부/경쟁 조건 | 실제 Kakao 계정·GPU 품질 |
| MySQL migration | V1~V5 이행, 기존 ID 보존, 제약조건·JPA validate | RDS 장애 조치·운영 부하 |
| Python 실행/연결 도구 | 설정·파일 권한·process 소유권·SSH·복원 보호 | 실제 팀원 PC 접속 성공 |
| 배포 설정 회귀 | env·Compose·프록시·백업 설정의 계약 | 자동 실배포·실계정 서비스 완주 |

```sh
./gradlew test
python3 -B -m unittest discover -s scripts/tests -p 'test_*.py' -v
python3 -B -m unittest discover -s deploy/tests -p 'test_*.py' -v
node --test integration/tests/*.test.mjs
```

일반 서비스/JPA 시험은 H2를 사용한다. [MySQL 이행 검사](../src/test/kotlin/com/hanyang/backend/migration/MySqlMigrationIntegrationTest.kt)는 Docker 또는 별도로 준비한 격리 MySQL 테스트 schema가 필요하다. 환경 부족으로 skip됐다면 MySQL 검증 성공으로 계산하지 않는다. 테스트 schema를 정리하므로 앱 DB에 연결해 실행하지 않는다.

모의 제공자·AI HTTP 서버는 오류·응답 순서·중복 전달을 재현하기 위한 도구다. 실제 OAuth 로그인이나 추론 성능의 대체 증거가 아니다.

## 과거 실행 기록: 2026-10-14

기존 한 방의 원본 사진 네 장으로 **실제 CUDA 분석 → 사진별 보정 → 재구성 → native GLB 검증·저장 → 매물 선택 → 익명 뷰어**를 자동화로 확인했다. 로그인은 fixture, 주소·가격은 예시였다. 사용자가 직접 촬영하거나 수동으로 전체 시연을 완료한 기록은 아니다.

| 항목 | 당시 확인 결과 | 해석의 한계 |
|---|---|---|
| 최종 방 모델 | 점 8개·간선 12개, 연결요소 1개 | wireframe이며 면·텍스처·실측 정확도 보증 없음 |
| 부동산 브라우저 검사 | 7묶음, 페이지 오류 0 | 실제 OAuth·실주소 제공자 검증 아님 |
| 재시작 보존 | 선택 모델·파일 15개 확인 | 저장소 장애·모든 종료 조건 보증 아님 |
| 별도 DB/media 복원 | 테이블 16개, FK 36개·위반 0, media 48개 | 기존 DB를 덮어쓴 복원이나 RDS 재해 복구 아님 |
| 실제 AI 재시작 | 완료 작업·geometry 보존, 완료 작업 재실행 없음 | 실행 중 CUDA 강제 종료·중간 계산 재개는 미검증 |

실제 결과는 한 공간의 제한된 사례다. 다른 방의 품질과 실측 오차는 별도 평가가 필요하다. 당시 배포 preview도 실로그인·새 사용자 등록·새 추론이 모두 가능한 상시 서비스로 보장하지 않는다.

## 과거 실행 기록: 2026-10-16

### 실제 로그인·AI 담당자 PC 연결 준비

실제 연동용 production JAR를 기존 시연과 다른 MySQL schema·계정·media·포트에서 실행했다. 테스트 인증 클래스가 JAR에 없음을 확인하고, V1~V5·16개 테이블과 기존 데이터·파일·설정 불변을 대조했다.

readiness `200`, 인증 없는 내 정보 `401`, 미설정 Kakao code/시연 문자열 토큰 `503`을 확인했다. 이는 키가 없을 때 가짜 성공을 만들지 않는 검사이며 **실제 Kakao 로그인 성공은 아니다**. 해당 새 서버는 검사 후 정상 종료했다.

| 도구 회귀 | 통과 수 | 범위 |
|---|---:|---|
| 실제 연동 실행기 | 29 | production JAR·설정·실행/종료 보호 |
| SSH·AI 준비 검사 | 35 | 연결 소유권·readiness·실제 모델/GPU·사진 GET 검사 경계 |
| 배포 설정 | 71 | Compose·env·백업 등 설정 회귀 |
| 합계 | **135** | 위 세 묶음의 합이며 실제 E2E 횟수가 아님 |

같은 날 Kotlin 선택 회귀 7클래스·43개도 H2/로컬 모의 제공자 환경에서 통과했다. 이는 별도 실행이므로 위 135개와 하나의 전체 서비스 시험처럼 합산하지 않는다.

### 가구 수동 배치의 표시·export 재생 검사

기존 실제 AI 결과와 가구 파일을 사용해 수동 배치 화면 → GLB export → 뷰어 재표시를 검사했다. 관련 기존 프론트 테스트 **18개**가 통과했다. 프론트·AI 소스나 실제 매물 데이터는 이 검토에서 수정하지 않았다.

이는 기존 결과를 이용한 재생 검사다. **새 팀원 PC 추론·실제 업로드·가구 포함 저장 후 서버 재조회 전체 흐름은 미검증**이다. API 불일치, 가구 파일명·CORS, 크기 metadata와 AI 좌표 단위/스케일 합의가 남아 있다. 프론트/AI 구현 전체를 이 공개 백엔드 저장소의 개인 성과로 계산하지 않는다.

## 과거 부하 실험은 별도로 보존

[최초 분석 Outbox 실험](../performance/README.md)은 로컬 단일 백엔드·제어된 Fake AI에서 두 방식을 교차 5회 실행한 과거 기록이다. baseline 504건 중 AI 접수 106건(21.03%), Outbox 503건 중 접수 503건(100%)을 관측했다. baseline의 398건은 AI가 `503`으로 거부한 요청이며 조용한 유실로 해석하지 않는다.

원래 manifest·요약 수치를 유지한다. 이 숫자를 후속 보정/재구성 경로, 실제 GPU 처리량, 현재 운영 SLA나 exactly-once 성과로 확대하지 않는다. 이번 공개 갱신에서 해당 부하 실험을 다시 실행한 것은 아니다.

## 현재 팀과 확인할 항목

실제 Kakao 앱 설정과 동일 Redirect URI로 한 계정의 로그인부터 확인해야 한다. 최신 프론트의 legacy/V2 요청을 맞추고, AI 담당자 PC의 코드 버전·GPU·가중치·접속 경로와 양방향 사진 GET/callback을 확인해야 한다.

최종 E2E는 **실로그인 → 서로 다른 사진 4장 등록 → 분석 → 사용자 보정 → 재구성 → 가구 수동 배치 → GLB 업로드 완료 → 매물 공개·재조회**다. 성공/실패 상태와 자산 귀속을 함께 확인할 예정이다. 2026-10-21 현재 실제 Kakao 및 팀원 PC의 이 전체 흐름이 성공했다고 기록하지 않는다.

사진·모델·DB dump·비밀 설정·접속 로그는 공개 자료에 포함하지 않는다. 설계 판단과 경계는 [설계 사례](engineering-cases.md)의 코드·테스트 링크로 확인할 수 있다.
